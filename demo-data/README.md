# Demo data provenance

Everything in `flights/` is generated by `scripts/precompute-demo-flights.ts` and is safe to
regenerate at any time (`npm run precompute`) - nothing here is hand-edited.

## Trajectories

`*-baseline.json` files contain the "actual" flight: a **reconstructed, representative**
trajectory (real city pair, real aircraft type, great-circle route, realistic phase-of-flight
altitude/speed profile), not raw recorded ADS-B telemetry. See `src/data/demoFlights.ts` for the
full disclosure and `Flight.dataProvenance` on every flight object.

## Atmospheric conditions

Every `AtmosphericSample` in these files comes from `DemoDatasetProvider`
(`src/data/providers/demoDatasetProvider.ts`), which is backed by a **synthetic, deterministic,
physically-motivated** atmospheric field (`src/science/atmosphericField.ts`) - not a live weather
model run or a replay of real CoCiP/ERA5 output. It exists because this build environment has no
outbound network access to call the real APIs. It is built from:

- the real ICAO Standard Atmosphere temperature/altitude relationship,
- the real Schmidt-Appleman-criterion and ice-supersaturated-region logic used by the actual
  CoCiP model, and
- energy-forcing magnitudes sampled from the **real, published CoCiP percentile distribution**
  (including the documented ~35% net-cooling fraction) at
  <https://apidocs.contrails.org/ef-interpretation.html>.

Every sample is tagged `providerId: "demo-dataset"` and `confidence: "low"` or `"medium"`
(never `"high"`) specifically so it can never be presented as equivalent to live data.

## `demo-jfk-lhr-b789-full-analysis.json`

A fully precomputed run of the pipeline (baseline + all 15 standard counterfactual strategies +
Pareto frontier) for the primary demo flight, intended as the guaranteed-working fallback
described in spec section 41 ("switching to verified demo dataset") if live in-browser
computation has a problem. Each counterfactual's per-waypoint `annotated` array is stripped from
this file (it's fully re-derivable - the engine is deterministic, see the determinism test in
`src/science/__tests__/pipeline.test.ts`) to keep the bundle size reasonable.

## Regenerating

```bash
npm run precompute
```

This re-runs the full engine and overwrites everything in `flights/`, printing validation output
(critical windows found, knee-point strategy, Pareto frontier size) to the console.
